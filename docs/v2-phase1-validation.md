## 人工验收

1. 在测试浏览器或隔离的浏览器配置中准备 V1 JSON 备份；保留正式网站数据，先导出再测试。访问本分支本地运行版本，导入 V1，核对所有习惯及旧记录。
2. 有原 v1 存储时，在首次保存前下载“升级前原始数据”；保存后检查新键为 v2、原 v1 原文不变。导出 v2，重新导入并核对分类、排序、备注和计划历史。
3. 创建自定义分类、重命名、分配并筛选；删除分类，确认习惯和记录仍在，只变为未分类。
4. 新建每天、指定星期、周 3 次习惯；验证星期选择与 1～7 次限制。编辑周期后查看下周一生效提示，检查历史月度统计未变化。非计划日禁止打卡但允许备注；周次数不进入每日分母。
5. 保存习惯当天/历史备注及当天/历史总结，取消打卡后核对备注仍在；归档保留备注，打卡历史沿用 V1 只读与归档当天移除规则。
6. 全部视图拖动并刷新，手机点击上移/下移及键盘操作，检查顺序持久化；分类筛选时不提供排序按钮。
7. 检查原有新建、编辑、日历补记/撤销、统计、归档、永久删除、导出导入及损坏恢复。多标签操作应提示旧标签只读。
8. 在真实 iPhone Safari 上检查日期输入、备注键盘、分类表单、弹窗焦点、滚动及排序按钮；本次只自动验证 Chromium 和 360px 视口，没有执行真实 iPhone/Firefox/WebKit 测试。
9. PR 合并与发布由维护者审核后决定；本分支不执行部署。若回滚至 V1，先保存 v2 备份，旧 v1 副本不会包含升级后新增的数据。

## 限制

计划编辑统一下周一生效；周计划达标率/达标周连续留阶段 2。备注最多 2000 字，JSON 仍限 5 MiB。没有云同步，localStorage 并非事务数据库，极端同时写入仍有竞争风险，应使用单标签编辑。真实手机 Safari 尚需人工验收。
