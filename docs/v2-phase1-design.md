# V2 阶段 1 技术设计

## 审查与范围

现有 React 19 / TypeScript / Vite 应用，Node 24，纯 localStorage，哈希路由。无 AGENTS.md。Pages base `/habit-tracker/`，仅 main 部署；完整 CI 包含格式、单元测试、构建和 Chromium。保留现有架构，不接入 Supabase、不实现热力图、趋势或主题。

## 模型

schemaVersion 2：habits、completionRecords、categories、notes 和 revision。习惯 ID 保持不变；分类 UUID；预设分类固定 ID。打卡 ID 是 JSON 编码的 [habitId,date]；备注 ID 是 [habitId|null,date]，null 表示当天总结。撤销打卡不删除备注。habit.order 保存全局顺序；categoryId 可为空。scheduleHistory 保存稳定 ID、生效日期及 daily / weekdays(ISO 1～7) / weeklyQuota(1～7)。这些实体可映射后续数据库；同步所需用户隔离、变更日志、删除墓碑和冲突协议留待阶段 3，当前不声称提供同步。

## 日期、统计和计划历史

日期是设备本地日历 YYYY-MM-DD；UTC 仅做无 DST 的日历算术。旧日期跨时区不重解释。周一至周日为一周，周以周一日期标识，跨年不使用自然年份+周号。每天和指定星期才进入每日/月度完成率；无计划日分母为零，显示暂无数据。weeklyQuota 任意有效日可打卡，每日最多一次，不进每日分母，达标统计留阶段 2。连续天数仍是实际连续日打卡，不能称连续达标周；非计划日不代表计划失败。

首次计划从创建日生效。所有计划编辑从下周一生效，当前周和历史保持不变；同一未来生效日可替换尚未生效的计划。归档日为排他截止，沿用 V1 移除当天打卡规则；备注保留且仍可编辑有效历史日期。分类删除仅解除关联。排序只在全部视图修改，手机和键盘提供上移下移，桌面拖动为附加方式。

## 迁移和恢复

先完整校验 v1，再确定性补全记录 ID、默认每天计划、未分类和原数组排序；幂等转为 v2。只读取不会改写 v1。首次写入新键 daily-progress:v2 时，再核对旧键内容，并保留旧键原文；v2 存在后优先读取 v2，损坏时绝不回退覆盖。旧标签页修改 v1 触发冲突。迁移前可导出原始 v1；读取权限/容量失败进入只读。恢复导入沿用显式确认整体替换且允许先备份，支持 v1/v2，拒绝无效引用、重复标识和未知版本。v1 键是回退副本而非实时镜像，V1 回滚不包含升级后的新记录。

## 风险和文件计划

主要风险：导入验证遗漏、历史计划误改、配额失败、V1 回滚数据不同步、多窗口非原子竞争。通过严格重建已知字段、历史计划测试、存储写入失败及冲突测试验证。浏览器 localStorage 不提供事务，极端同时写入竞争沿用既有单标签使用限制。修改 domain/storage、components/App/styles、测试和 README；不改锁文件、Pages base 或部署工作流。iPhone Safari 需人工验收。

## 阶段 2 接口约定（仅设计）

每日趋势的分子是计划日已完成的 habit-date 数，分母是该日 daily/weekdays 的计划数；零分母为 null，不能画作失败或 0%。历史图必须逐日读取 scheduleAt，包含当时有效的归档习惯。

每周 N 次以周一日期为周期 ID，分子为该周有效的不同打卡日期数，达到 N 即达标；每周计划达标率是已达标完整周 / 已结束完整计划周。创建或归档造成的不足整周不纳入达标率分母，当前未结束周仅显示进度、不能预判失败；不折算 N、不把次数塞进每日分母。连续达标周只计算连续、已结束、完整且同类计划的周，非 weeklyQuota 周以及不足整周划开序列，当前进行中周不清零上一已结束周的连续。未来阶段需按此规则独立实现与测试，本阶段不展示达标率或达标周连续。

归档当天的打卡继续采用 V1 的显式确认移除规则，但当天备注保留并可编辑。读取迁移本身不写存储，界面在首次保存前提供原文下载；回滚时先导出 v2 新数据。
