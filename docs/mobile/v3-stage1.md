# V3 阶段 0 审计与阶段 1 交付

## 审计结论

开发基线为手机端分支 82cf852。此前 set_checkin 与创建/编辑/归档共用全局写锁，每次成功写入都读取完整 read_snapshot 后才更新按钮，造成延迟和串行操作。已有嫩芽图标、双 Base 配置、独立预览 Auth key、7 天空闲/30 天期限可复用。

当前习惯模型为字符串 ID、名称、颜色、创建日期与含归档当天的 archived_on；打卡按习惯和日期唯一。read_snapshot SQL 返回当前用户全部习惯与历史，不限当月。habit_mobile 两张表开启 RLS/FORCE RLS；五个业务 RPC 是 SECURITY INVOKER、空 search_path、按 auth.uid() 隔离。业务日期保持 Asia/Shanghai。旧 001/002 是历史同步设计，本阶段未执行或修改任何 SQL。

## 本轮实现

- 已确认快照与临时打卡 overlay 分离。同一习惯保存期间锁定，其他习惯可独立写入；历史日历复用相同目标状态 RPC。没有离线队列。
- 每次操作包含序号和账号 epoch；退出/账号变化中止等待并丢弃旧响应。读取按账号与写入修订合并；旧快照不能覆盖更新的确认结果。
- 成功 RPC 直接确认该日期的完成目标，不再每次重读全部历史。创建、编辑、归档仍保留原确认后刷新流程，打卡未结束时暂不执行结构变更。
- 失败撤销对应临时状态、保留其他习惯的 pending；不确定结果先读服务器核对，读取也失败时锁定到下一次成功刷新。不自动重发写入，不把超时当成服务端事务回滚。
- RPC/读取等待上限 15 秒，支持 AbortSignal。取消请求不能保证数据库尚未提交，已提交数据不删除；对账只确认读取时的状态，不能提供跨设备版本冲突保证。
- 卡片确认后 450ms 对勾反馈；今日全部确认完成时 1.8 秒轻量反馈。取消、初始历史和普通刷新不庆祝；不确定写入即使对账读到完成也不庆祝。按应用、项目、用户和日期保存极小的全完成庆祝标记，仅用于防止重复播放，不保存业务记录或令牌。尊重减少动态效果设置。
- 认证恢复及首次必要读取使用嫩芽启动画面，不人为延迟、不显示伪百分比；失败/超时提供刷新，数据初始化失败时也允许退出。初次读取与同版本唤醒请求合并。
