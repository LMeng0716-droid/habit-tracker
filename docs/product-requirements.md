# 「每日进步」第一版产品需求

版本：调研后建议稿，2026-10-08。本文是待审查的产品方案，不代表已实现功能。证据及许可证见[开源调研](open-source-research.md)；开发顺序见[开发计划](development-plan.md)。

## 1. 产品定位与范围假设

面向希望培养阅读、运动、早睡等日常习惯的中文用户，核心价值是“打开就能记录今天，回头能看到积累”。默认形态为手机优先、桌面可用的网页应用；暂不以微信小程序或原生App为目标。第一版免注册、无服务器，只支持同一浏览器同一站点下的单设备数据；没有自动跨设备同步。

核心用户故事：我创建“阅读10分钟”，每天一键打卡；误点可撤销；忘记昨天可在月历补记；月底能看完成天数与连续记录；更换设备前能导出备份。首版统一每天一次、二元完成，名称可以表达行为，但不解析“10分钟”或自动计时。

## 2. 页面结构与主流程

手机底部三个入口：**今天 / 统计 / 设置**；桌面可同样使用导航。习惯详情和编辑从今天列表进入，不增加过多一级入口。

| 页面/区域 | 内容 | 主要交互和状态 |
| --- | --- | --- |
| 今天（首页） | 中文日期、今日完成X/Y、习惯列表、添加按钮；卡片显示名称、今日状态、当前连续 | 大按钮“打卡”→“已完成”；再次操作明确“撤销打卡”；卡片标题进入详情。空列表引导创建，不默认写入示例数据 |
| 新建/编辑（弹窗或子页） | 名称、预设颜色；规则固定每天一次 | 名称去除首尾空白，1～30个Unicode码点；建议名称不同，重名警告可继续。保存/取消清晰；退出未保存提示 |
| 习惯详情 | 当前/最长连续、累计完成天数、按月日历、编辑与归档菜单 | 月份切换；选择有资格日期，打开状态面板再确认补记/撤销，防止误触；未来日期禁用 |
| 统计 | 各习惯选定月份完成天数/有效天数/完成率，当前与最长连续 | 先数字和简单进度条；当前/最长连续注明为全部历史，月份筛选只影响完成率。无有效天数显示“暂无数据” |
| 设置 | 本地存储说明、JSON导出/导入、归档列表、清空数据、版本信息 | 导入预览后确认整体替换；归档习惯可查看/导出；清空需二次确认并提供备份入口 |

首页把打卡放在第一屏，月历放详情，避免每张卡片展开两个月；颜色配合文字/符号传达状态。使用“今天还未完成”“累计完成12天”等中性中文，不用失败惩罚或“进度归零”制造压力。

## 3. 功能优先级

P0均为第一版发布门槛；P1是第一版稳定后的候选，不应拖延P0；P2明确不进第一版。

| 优先级 | 功能 | 验收要点 |
| --- | --- | --- |
| P0 | 创建/编辑习惯、今天打卡与撤销 | 刷新后名称与状态保留；同一习惯同一日期只有一条完成记录 |
| P0 | 真实日期历史、月历、补记/撤销 | 跨周跨月跨年不覆盖；禁止未来、创建前、归档起始日及之后日期；空白日期有状态说明 |
| P0 | 当前连续、最长连续、累计与月完成率 | 使用明确规则；补记和撤销后即时重算，不靠缓存计数 |
| P0 | 归档、查看历史、永久删除 | 归档保留记录并退出今天列表；第一版不恢复归档，避免暂停区间的隐含规则；永久删除说明将同时删记录，二次确认 |
| P0 | 本地持久化与错误处理 | 读写失败不能伪装成功；数据损坏不自动覆盖原内容；多标签并发有冲突提示 |
| P0 | JSON备份导出与替换导入 | 导出含格式版本；导入先校验和预览，失败不改现有数据；先提醒导出现有数据 |
| P0 | 中文与手机可用性 | 360px宽无横向滚动；按钮至少44px触控目标；键盘可操作、焦点清晰，弹窗关闭后还原焦点 |
| P1 | 搜索/排序、主题切换、CSV导出、短备注 | 用户习惯数量或真实反馈证明需求后再做 |
| P2 | 社交、云同步、AI、复杂计划、游戏化 | 不属于第一版范围 |

## 4. 日期和统计规则（必须统一）

1. **日期身份**：记录设备本地日历日期 `YYYY-MM-DD`，以当地午夜切换今天；用本地年月日生成，不能用UTC ISO字符串截取。时间戳仅用于创建/更新审计。跨时区后今天按新设备时区判断，旧记录日期保持不变；无云端校时，修改系统时钟可能影响操作范围。
2. **有效日期**：每天一次；范围为创建当天至今天。归档从操作当天开始不再要求打卡；若当天已有完成记录，归档确认须说明当天记录将移除，之前历史保留。归档之后详情为只读，不能补改任何日期；永久删除与清空是另外明确的破坏性操作。
3. **当前连续**：今天已完成，从今天向前逐日计算；今天未完成但昨天完成，从昨天计算并提示“今天尚未完成”；今天和昨天均未完成则0。例：周一、二完成，周三上午未打卡显示2；周三补上显示3；周四整天未完成，周五显示0。归档习惯不显示“当前连续”，只显示历史最长与累计。
4. **最长连续**：所有历史真实日期中最长无缺口序列；周日到周一、月末到月初均连贯。补记可连接两段，撤销中间日期可拆成两段。不能用最长连续代替当前连续。
5. **月完成率**：分子为该月有效日期中的完成天数；分母为该月创建日期起至今天（含今天）的有效自然日；归档截止前一天。例：10月5日创建，到10月8日完成3天，显示3/4、75%；本月未来天数不计。分母0时显示“暂无数据”，不显示0%。显示百分比四舍五入为整数，同时保留X/Y以便解释。
6. **今日整体进度**：今天未归档习惯的完成数/总数；总数0显示“创建你的第一个习惯”，不计算百分比。各习惯独立统计；第一版不做难以解释的加权总得分。
7. **日历**：周一作为一周起点，中文“周一…周日”；区分今天、完成、未完成、不可操作日期；状态至少有文字/可访问标签，不能仅靠颜色。

## 5. 数据、安全和可靠性要求

- 提示“数据保存在当前浏览器；清除站点数据、更换浏览器或设备可能导致记录不可用，请定期备份”。不声称本地存储永久可靠或数据加密。
- 默认不上传、不引入分析追踪、广告或第三方登录；资源尽量同源，不依赖外部字体。打开过网页不保证离线可用；第一版不承诺PWA缓存或离线首次启动。
- 导入仅支持自己导出的版本化JSON，单文件上限5MiB，校验结构、真实日期、唯一ID、引用、记录范围和日期去重；未知版本拒绝。不得把名称作为HTML解析或执行任何导入内容。
- 导入为整体替换，不做自动合并。先在内存校验、展示习惯/记录数量，再确认；单次保存完整数据，保存失败保留原数据并提示。恢复和备份往返必须可测试。
- 多标签窗口仅单写者：检测storage事件或版本变化，旧窗口进入只读并提示刷新，不静默覆盖新数据。第一版不做复杂实时协同。
- 存储不可用时禁用修改并显示原因和已有数据导出选项；损坏数据显示恢复入口，不能把“读不到”当“空数据”自动保存。

## 6. 第一版明确不开发

- 账户、登录、服务器、云数据库、多端自动同步：增加权限、冲突、安全与持续运维。
- 每周几次/隔天/指定星期、暂停休假、每天多次或计量目标：会改变有效日期、连续和完成率定义。
- 推送提醒、后台定时通知、PWA离线缓存、桌面小组件：受浏览器/系统权限和生命周期限制。
- 连续冻结卡、积分宠物、排行榜、社交分享和付费订阅：偏离轻量记录目标，也引入额外规则与资产许可。
- AI教练、生成计划、健康判断：需要额外数据、成本和准确性控制。
- 年度热力图、复杂图表大屏、长篇日记、多语言系统、原生Android/iOS或微信小程序：维护成本高，先观察真实使用反馈。

## 7. 第一版验收场景

创建“阅读10分钟” → 打卡 → 刷新 → 查看详情 → 补记符合范围的昨天 → 检查跨月连续 → 撤销 → 导出 → 清空确认 → 导入备份，习惯和历史一致。存储异常、坏JSON、未来日期和多窗口冲突不造成静默丢失。无网络请求上传用户打卡数据。

本次需求有三项需在后续开发任务开始时明确接受或调整：网页形态、每日一次、单设备本地数据。现在按这些合理默认值提供完整方案，不提前写应用。
